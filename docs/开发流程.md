# KeyboardMouseHeatmap 开发流程与总体方案

## 1. 项目定位

KeyboardMouseHeatmap 是一个 Windows 优先的桌面统计工具，用于记录键盘按键和鼠标操作次数，并通过键盘、鼠标模板和时间图表展示使用习惯。

核心体验是：用户打开软件后，可以直观看到“哪些键最常用”“什么时候使用最多”“键盘和鼠标的操作分布是什么样”。

## 2. 已确认的技术栈

| 层次 | 选择 | 用途 |
|---|---|---|
| 桌面容器 | Tauri 2 | 窗口、系统托盘、打包和前后端通信 |
| 原生后端 | Rust stable | 全局输入监听、计数聚合、数据库访问 |
| Windows API | `windows` crate | 键盘和鼠标低级事件监听 |
| 前端 | Vue 3 + TypeScript + Vite | 页面和交互 |
| 状态管理 | Vue Composition API，必要时再引入 Pinia | 时间范围、统计数据和设置状态 |
| 数据库 | SQLite | 本地保存聚合统计 |
| 数据访问 | `rusqlite` 或 `sqlx` | Rust 侧数据库读写 |
| 图表 | ECharts | 趋势图、时间热力图和排行 |
| 模板绘制 | SVG + CSS | 键盘、鼠标和热力颜色 |
| 日志 | Rust `tracing`，前端必要时使用轻量日志 | 诊断和开发记录 |
| 测试 | Rust 单元测试 + 前端 TypeScript/Vitest 测试 | 验证计数、聚合和界面逻辑 |

## 3. 为什么选择 Tauri + Rust

### 优点

- 前端可以快速制作丰富的可视化界面和动画
- Rust 适合处理系统级输入事件和长期后台运行
- Tauri 程序体积和内存占用通常小于 Electron
- 前后端职责清晰，未来可以替换或扩展界面
- SQLite 和本地离线运行天然适合隐私优先的统计工具

### 需要提前注意的问题

- 全局输入监听属于 Windows 原生能力，需要自己封装监听线程和消息循环
- 普通权限下可能无法观测某些高权限程序或受保护界面的输入
- 游戏、反作弊软件、UAC 安全桌面等场景不保证可统计
- Tauri Command/Event 的数据边界要设计清楚，避免前端直接接触原始事件
- 默认不应保存原始按键流，防止统计工具变成键盘记录器

```text

  - 事件标准化

          │
          ▼

          │
          ▼
Vue 前端
  - 键盘 SVG 热力图
  - 鼠标 SVG 热力图

  - 趋势图
  - 筛选和设置
```

## 5. 统计规则

### 键盘

- 默认统计“物理按键次数”，同一次长按产生的系统自动重复不重复累计
- 修饰键如 `Ctrl`、`Shift`、`Alt`、`Win` 单独统计
- 优先保存物理扫描码和规范化按键 ID，避免输入法和键盘布局影响热力图
- 不保存 `A`、`B` 等组成的完整文本，不保存密码、聊天内容或文档内容
- 后续可以增加“原始 KeyDown 事件模式”，但必须由用户主动开启

### 鼠标

- 左键、右键、中键、侧键分别统计
- 滚轮向上和向下分开统计
- 默认不记录鼠标坐标，除非未来明确增加屏幕区域热力图功能

### 时间

- MVP 至少保存日期级统计
- 为支持时间热力图，同时保存小时级聚合
- 所有统计以本机本地时间展示

## 6. 建议的数据结构

```sql
CREATE TABLE IF NOT EXISTS key_stats (
  stat_date TEXT NOT NULL,
  stat_hour INTEGER NOT NULL,
  key_id TEXT NOT NULL,
  key_label TEXT NOT NULL,
  press_count INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (stat_date, stat_hour, key_id)
);

CREATE TABLE IF NOT EXISTS mouse_stats (
  stat_date TEXT NOT NULL,
  stat_hour INTEGER NOT NULL,
  button_id TEXT NOT NULL,
  action_type TEXT NOT NULL,
  action_count INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (stat_date, stat_hour, button_id, action_type)
);
```

如需记录应用分类，应新增独立字段或表，并且默认关闭；不要把窗口标题或文档名称写入数据库。

## 7. 视觉设计方向

目标是“活泼、丰富、年轻”，但仍保持数据可读性。

建议设计变量：

```text
背景：#0F172A 深海军蓝
面板：#172554 深蓝紫
青色：#34D9FF
荧光绿：#2DE2A6
黄色：#FFD166
珊瑚红：#FF5C7A
紫色：#A78BFA
文字：#F8FAFC
次级文字：#94A3B8
```

热力等级建议从蓝色、青色、绿色、黄色过渡到橙红色。颜色不能单独承担信息，控件上应同时提供数字或悬停提示。
