# 技术决策记录

## ADR-001：选择 Tauri + Rust

- 日期：2026-09-04
- 状态：已确认
- 决策：使用 Tauri 2 作为桌面容器，Rust 作为原生后端

原因：项目需要全局监听键盘和鼠标，同时需要较丰富的现代化可视化界面。Tauri 可以使用 Web 技术制作界面，Rust 负责 Windows 原生输入和本地数据，体积和资源占用也适合常驻工具。

## ADR-002：前端使用 Vue 3 + TypeScript + Vite

- 日期：2026-09-04
- 状态：已确认
- 决策：使用 Vue 3、TypeScript 和 Vite

原因：当前 `F:\TauriProject\SerialTool` 已采用类似前端组合，可以复用使用经验；Vue 适合快速组织仪表盘、SVG 模板和响应式数据。

## ADR-003：数据库使用 SQLite

- 日期：2026-09-04
- 状态：已确认
- 决策：统计数据只存储在本机 SQLite

原因：数据量小、无需服务器、离线可用，适合隐私优先的个人工具。数据库保存聚合结果，不保存原始输入流。

## ADR-004：键盘模板使用 SVG

- 日期：2026-09-04
- 状态：计划采用
- 决策：使用 SVG 绘制键盘和鼠标模板，通过 CSS 变量和 Vue 数据绑定控制颜色与数字

原因：SVG 适合精确布局、悬停交互、响应式缩放和自定义主题，也方便支持 ANSI、ISO 和笔记本键盘布局。

## ADR-005：默认采用物理按键统计模式

- 日期：2026-09-04
- 状态：计划采用
- 决策：默认统计一次实际按键，不把操作系统长按重复视为多次按键

原因：热力图更能反映用户实际按键习惯，避免长按方向键或删除键造成计数失真。后续可提供高级选项切换统计规则。

## ADR-006：Windows Hook 与异步聚合

- 日期：2026-09-04
- 状态：已实现，待人工验收
- 决策：Windows 使用 `WH_KEYBOARD_LL` 和 `WH_MOUSE_LL`，Hook 回调只做轻量事件投递；独立聚合线程负责去重、统计、写入 SQLite 和发送快照事件。

原因：Hook 回调必须尽快返回，不能在回调中执行数据库查询或 UI 操作。分离监听和聚合可以降低输入延迟，并保留后续增加批量写入和节流推送的空间。

## ADR-007：前端保留浏览器预览回退

- 日期：2026-09-04
- 状态：已实现
- 决策：Vue 首页在 Tauri Command 不可用时使用演示数据，在 Tauri 运行时自动切换到本地 SQLite 数据。

原因：便于设计和前端开发阶段直接使用 `npm run dev` 预览，同时避免把“没有连接原生后端”误认为输入统计失败。

## ADR-008：MVP 提供系统托盘菜单

- 日期：2026-09-04
- 状态：已实现，待人工验收
- 决策：使用 Tauri 2 的 tray icon 能力提供“打开 KeyPulse”“暂停/继续记录”“清空本地统计”和“退出 KeyPulse”菜单。

原因：键鼠统计需要长时间后台运行，托盘是低干扰地查看和控制记录状态的基础入口；菜单动作复用现有 `RecordingState`、SQLite store 和前端事件，不引入第二套业务状态。

## ADR-009：自定义日期范围使用独立查询 Command

- 日期：2026-09-04
- 状态：已实现，待人工验收
- 决策：保留 `get_dashboard(range)` 的预设范围接口，新增 `get_dashboard_custom(start, end)`；日期统一使用本地 `YYYY-MM-DD`，后端负责严格校验格式和起止顺序。

原因：预设范围和用户选择的任意历史范围语义不同，独立 Command 可以保持已有调用兼容，也让 SQLite 层明确执行闭区间查询，避免把日期校验逻辑散落在前端。

## ADR-010：Tauri 打包工具使用项目本地缓存

- 日期：2026-09-04
- 状态：已实现
- 决策：在 `src-tauri/tauri.conf.json` 的 `bundle` 中启用 `useLocalToolsDir`，让 WiX/NSIS 工具缓存位于项目 `target/.tauri`。

原因：项目位于 F 盘，而默认用户缓存位于 C 盘；Windows 在 NSIS 工具解压/移动阶段会触发跨磁盘 `os error 17`。项目本地缓存让构建路径保持在同一卷，并已验证 MSI 与 NSIS 均可生成。

## ADR-011：MVP 以小时桶表示活跃程度

- 日期：2026-09-04
- 状态：已实现
- 决策：当前 SQLite 只保存日期/小时聚合，真实数据界面显示“活跃时段”数量，不伪造精确的小时/分钟时长；浏览器预览继续使用演示数据。

原因：没有分钟级开始/结束事件时，精确活跃时长无法从小时桶可靠推导。先保持统计口径诚实，后续若需要精确时长，再单独设计活动会话或分钟级聚合模型。

## ADR-012：区分数据库可用与全局监听可用

- 日期：2026-09-04
- 状态：已实现，待人工验收
- 决策：启动时通过 `InputStatus` 和 `get_input_status` 暴露 Windows Hook 是否成功；数据库仍可读时，前端显示“监听不可用”警告并禁用记录按钮，而不是显示“本地实时数据”。

原因：SQLite 初始化成功并不代表低级输入 Hook 一定成功。拆分这两个状态可以让用户继续查看历史数据，同时明确知道当前不能产生新的统计。

## ADR-013：应用内提供隐私与权限说明弹窗

- 日期：2026-09-04
- 状态：已实现，待人工验收
- 决策：主界面头像按钮（KP）打开“隐私与权限说明”弹窗，说明只保存聚合统计、全程本机处理、随时可暂停/清空，并提示管理员窗口、UAC 安全桌面等 Hook 观测限制和本地数据库路径。

原因：键鼠统计属于敏感能力，隐私承诺不能只写在 README 里——用户不应需要查阅仓库文档才能理解数据行为。弹窗使用 `role="dialog"`、`aria-modal`，打开时自动聚焦、支持 ESC 和关闭按钮，保证可访问性；内容与 ADR-003/ADR-005、README 隐私原则保持同一口径。
